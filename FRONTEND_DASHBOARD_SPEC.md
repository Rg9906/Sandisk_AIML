# WaferLens: Industrial Multi-Resolution Die Yield Dashboard
## Comprehensive Frontend Architecture & Implementation Specification

> **Document Purpose**: This document serves as the complete, self-contained technical specification for building the industrial-grade web dashboard for the **SanDisk / Western Digital Multi-Resolution Die Yield Prediction** project. Any AI engineer or developer can consume this specification to implement, extend, or skin the application across React/Vite, Next.js, or Streamlit.

## 1. Executive Summary & Problem Context

In advanced 3D NAND flash memory fabrication, silicon wafers contain thousands of dies arranged on a regular grid. Each die undergoes wafer probe testing with:
1. **Die-Level Electrical Parametrics**: ~500 continuous continuous measurements (low SNR, median effect size Cohen's $d \approx 0.14$).
2. **Spatial Wafer Context**: Neighborhood pattern, radial distance, and transductive wafer priors.
3. **Sub-Die Block Readings**: 2,000 sub-die physical measurements per die capturing fine-grained internal degradation.

### Machine Learning Benchmark Ground Truth (Current Backend)
The backend model (**WaferLens Model B**) is a **Calibrated Convex Hybrid Ensemble** fusing:
- **PyTorch Gated Attention-MIL** over 2,000 block readings (`val AUC-PR = 0.6041`).
- **5-Seed Bagged LightGBM** over die parametrics & Empirical-Bayes spatial priors (`AUC-PR = 0.5790`).
- **Shipped Performance**: **`0.6074` AUC-PR**, **`97.18%` Accuracy**, **`77.01%` Precision**, and **`80.10%` Cost Savings** ($24,238 expected cost vs. $96,610 for the incumbent GDBN standard).
- **Core Scientific Finding**: Block readings rescue **49 true defect dies** that die-level models miss, and eliminate **132 false alarms**.

## 3. Data Ingestion & Data Contracts

The frontend consumes pre-computed inferences and reports generated by the backend pipeline:
1. `results/preds_full.pkl`: Pickled dictionary containing:
   - `preds`: List of 29,806 prediction objects.
     - `p.wafer_id`: Wafer string (e.g. `wafer_042`).
     - `p.die_x`, `p.die_y`: Integer die grid coordinates.
     - `p.p_fail`: Calibrated probability $[0.0, 1.0]$.
     - `p.conformal_lo`, `p.conformal_hi`: Confidence interval bounds.
     - `p.y_true`: Ground truth label ($0$ or $1$).
     - `p.y_pred`: Binary classification ($0$ or $1$).
     - `p.attribution`: `{"die": float, "spatial": float, "block": float}` (sums to 1.0).
     - `p.root_cause`: Diagnostic string (e.g., *"Donut: Residue resistant to photoresist cleaning | ACTION: Clean / strip step review"*).
     - `p.consistency`: `{"status": "AGREE" | "PARTIAL" | "DISCREPANT", "score": float}`.
     - `p.block_attention`: 100-D array of attention weights across block chunks.
2. `results/comparison.md`: Markdown comparison tables, economics, and rescue analysis.
3. `results/results.csv`: Benchmark history across all waves and models.
4. `figures/*.png`: Generated static plots (attribution, PR curves, attention profiles).

## 4. Multi-Page Functional Specification

The dashboard consists of **6 cohesive, specialized pages**:

```
├── 1. Executive KPI Command Center      (Overall fab health, benchmark vs GDBN/DPAT)
├── 2. Interactive Wafer Map Explorer    (Wafer grid, heatmaps, hover/click die selection)
├── 3. Die Diagnosis & Sub-Die Heatmap   (Attribution, 2000-block attention, root cause action)
├── 4. A → B Rescue & Regression Lab     (B_RESCUE dies, overkill cleanup, signature clusters)
├── 5. Fab Economics & Simulator         (Cost sliders, threshold tuning, PR/ROC curves)
└── 6. Engineering AI Copilot            (Grounded natural-language root-cause queries)
```

### Page 2: Interactive Wafer Map & Die Explorer

#### Objectives
The visual flagship of the application: renders the circular semiconductor wafer with full interactivity.

#### Key UI Elements
1. **Wafer Selector**:
   - Dropdown showing 40 test wafers with die counts and failure rates.
2. **Interactive Multi-Layer Wafer Canvas**:
   - **Mode A: Pre-Test Map**: Passing dies vs. pre-test dead dies (`old_label = 1`).
   - **Mode B: AI Failure Risk Heatmap**: Continuous gradient ($0.0 \rightarrow 1.0$) using Plasma or Turbo colormap.
   - **Mode C: Post-Test Ground Truth**: Highlights true newly failed dies (`y_true = 1`).
   - **Mode D: Classification Outcome**:
     - *True Positive (Green)*: Caught defect.
     - *False Positive (Amber)*: Yield overkill.
     - *False Negative (Red)*: Escaped defect.
     - *True Negative (Slate)*: Passing die.
3. **Interactive Tooltip on Hover**:
   - Shows: `Coordinates (X, Y)`, `Risk Score`, `Conformal Band [Lo - Hi]`, `Ground Truth`.
4. **Click-to-Inspect**:
   - Clicking any die locks it as the active selection and loads Page 3.

### Page 3: Deep-Dive Die Diagnosis & Sub-Die Block Heatmap

#### Objectives
Directly satisfy Sandisk Criterion 3 (30% interpretability): *"Every prediction is an engineering diagnosis, not just a probability."*

#### Key UI Elements
1. **Selected Die Header**:

2. **Multi-Resolution Attribution Stacked Bar**:

### Page 4: Model A $\rightarrow$ Model B "Rescue Lab"

#### Objectives
The core proof for Sandisk Criterion 4 (20% multi-resolution fusion): Demonstrating that block readings provide vital defect signals that die-level tests miss.

#### Key UI Elements
1. **4-Quadrant Contingency Grid**:
   - **`B_RESCUE` (49 Dies)** 🏆: Defect dies missed by Model A that Model B recovered!
   - **`B_CLEANUP` (132 Dies)**: Passing dies that Model A falsely wanted to scrap, but Model B saved.
   - **`BOTH_CAUGHT` (487 Dies)**: Strong joint failure detection.
   - **`B_REGRESSION` (24 Dies)**: Edge-case regressions.
2. **Net Rescue Gain Callout**:
   - **`+25 Net Defect Dies`** saved from shipping to customers.
3. **Failure Signature Mining Table**:
   - Lists the 5 physical patterns discovered among rescued dies:
     - **Clean Context (65.3% of rescues)**: *Proves block readings catch intrinsic degradation where spatial context looks clean.*
     - **Random Gross Excursion (14.3%)**
     - **Mechanical Handling Scratch (8.2%)**
     - **Photoresist Cleaning Donut (8.2%)**
     - **Localized Chamber Excursion (2.0%)**
4. **Interactive Rescued Die List**:
   - Allows users to click on any rescued die to inspect its block attention profile.

## 5. Technology Stack Implementation Options

This architecture can be built using either of two modern stacks:

### Option A: Streamlit Pro Dashboard (Fastest, Native Python)
- **Path**: `app/app.py`
- **Libraries**: `streamlit`, `plotly`, `pandas`, `numpy`.
- **Pros**: Directly imports backend prediction caches (`preds_full.pkl`) with zero REST API overhead. Runs via `streamlit run app/app.py`.

### Option B: React + Vite + Tailwind/CSS (Full Production Web App)
- **Backend**: FastAPI (`api/main.py`) serving endpoints:
  - `GET /api/kpi`
  - `GET /api/wafer/{id}/grid`
  - `GET /api/die/{id}/diagnosis`
  - `GET /api/rescues`
  - `POST /api/simulate`
- **Frontend**: React 18, Vite, Lucide Icons, Canvas/SVG for Wafer rendering, Recharts/Chart.js for PR curves.
- **Pros**: Extremely fast 60 FPS wafer rendering, sleek dark-mode glassmorphism, responsive navigation.
