The problem, and the three reasons it is hard

Predict which dies that passed pre-test will fail. Already-broken dies are input, never targets.
If you remember one thing
The rare class is also the ambiguous class. Both problems compound.
The task, drawn
pre-test fail will fail passes

6,753 dies are already dead. Of the 32,598 that look fine, 1,380 are about to fail. Those amber dies are the entire target.

The accuracy trap
95.77%

is what a model scores by predicting “everything passes” and catching zero failures. We select on AUC-PR. Accuracy is reported once, then ignored.

Hard thing 1 · Extreme imbalance

1,380 failures in 32,598 eligible dies. Any metric that averages over both classes is dominated by the majority.

Hard thing 2 · The classes almost completely overlap

Individually every one of the 500 parametrics is near-useless. But they are near-independent, so they add in quadrature. That single insight drove the whole feature design.

Hard thing 3 · The incumbent methods assume what is not true

Industry screenAssumptionAUC-PR
DPAT (3σ)Univariate Gaussian per parameter0.045
GDBN (5×5)Bad neighbours imply a bad die0.054
NNR (k=8)Residual against nearest neighbours0.073

With a median Cohen's d of 0.133 there is no single parameter for a univariate rule to threshold on. We reproduced the published critique of DPAT on our own data.

Three resolutions of evidence

Recon proved these channels are independent: neighbourhood badness does not show up in a die's own parameters (r = +0.015). So they are fused, not substituted.

Five questions. Each answer forced an architectural decision. This is why the system looks the way it does.
Method
Every design choice below is downstream of a measurement, not of a preference.
QuestionWhat we measured Decision it forcedWhat we would have done otherwise
Q1 · Failure rate 4.18% of eligible dies newly fail — inside the stated 2–5% band. All-pass scores ~95.8%. Select on AUC-PR; log accuracy but never optimise it. Reported accuracy and looked excellent while catching nothing.
Q2 · Are blocks ordered? Ordered. Lag-1 autocorrelation 0.250 vs a shuffled control of +0.001, decaying to 0 by lag 5. Run-length features are meaningful; attention has a real contiguous cluster to point at. Treated 2,000 readings as an unordered bag and thrown away the structure.
Q3 · Does GDBN's premise hold? Barely. 5×5 bad-neighbour ratio vs failure: +0.012 pooled, +0.018 within wafer. Between wafers: −0.187. Build the neighbourhood factory but expect little — put the effort into the wafer-level rate. Invested in multi-scale neighbourhood features that later measured −0.008.
Q4 · Are splits clean? All three overlaps zero — because we enforce it. And the kit's validation.parquet is test with labels dropped. By-wafer split with a hard assertion; validation carved from train. Tuned on the test set without knowing it. Every number invalid.
Q5 · Class overlap Median Cohen's d 0.133, best single feature 0.369 — but near-independent, so aggregate d = 3.44. Build an explicit pooled anomaly score over all 500 and feed the tree one strong feature. Hoped a tree would find one good feature among 500 weak ones. It cannot.
Q2 · Autocorrelation decay proves ordering
Q5 · Weak features add in quadrature

The trap we found in the supplied kit

validation.parquet is test.parquet with the label column dropped — the same wafers, identical row count. It is not a third split.

Any team that tuned on it tuned on the test set. We carve validation out of train by wafer and keep test as a true holdout, using the kit's file only to write the submission.

Rule we worked to

Decision 1 · How to handle the 2,000 block readings
Feed all 2,000 raw values to the model rejected
32,598 dies × 2,000 columns is 65M values. Trees cannot use it and the run would not finish in the window.
1D-CNN over the block sequence not built
Viable — recon Q2 proved the readings are ordered — but it needs tuning time we did not have. Documented as future work.
Attention-MIL, Ilse et al. 2018 built, benched
Gated attention tanh(V)⊙σ(U) makes block interpretability architectural. Scored 0.60 on early runs, 0.27 on the shipped run. Unstable — not shipped.
25 statistical aggregates shipped
Mean, spread, extremes, hot-block count, longest contiguous excursion, autocorrelation. +0.029 AUC-PR over Model A, stable across runs.
Decision 2 · How to use spatial context
Classical GDBN rule baseline only
Hand-set bad-neighbour threshold. We implemented it as a baseline: 0.054 AUC-PR. Kept for comparison, not for use.
Multi-scale neighbourhood factory measured −0.008
We expected this to be the win. The ablation says it cost us AUC-PR. Reported, not deleted.
Transductive wafer prior shipped · +0.046
Recon Q3 said the wafer's own failure rate carries the spatial signal, not the neighbourhood. Largest single feature win in the whole ablation.

Bars scaled between 0.55 and 0.59 so the differences are visible. Green is what shipped as the imbalance strategy; red is measured harm.

Rung 1 → 2 · the free lever

What worked, and why

  • Threshold tuning. Biggest lever, costs nothing. This is why our constraints file forbids leaving a threshold at 0.5.
  • Focal loss (Lin et al. 2017). Down-weights easy examples so gradient budget reaches the ambiguous overlap — where 65% of this dataset's failures sit by construction.

What failed, and why we say so

  • Class weighting alone. Recall 0.371 → 0.617 but AUC-PR barely moves. It relabels the same ranking rather than adding information. This is the most common mistake in the room.
  • Per-wafer adaptive weights. We expected a win. Measured 0.5729 vs 0.5859. Likely redundant with the transductive wafer prior, which already gives the model each wafer's rate.
  • SMOTE (Chawla et al. 2002). Worst rung at 0.5607. Synthetic points are interpolated between failures, and at d = 0.134 those land inside the pass distribution. You cannot resolve an overlap by manufacturing more points inside it.

Our position
Six things we expected to work did not. All six are measured, and all six are in the repository.

Each one changed the design rather than being quietly dropped. The wafer prior exists because the neighbourhood failed.

Honest limitations

  • 55.4% escape rate at the shipped cut
  • The +0.029 A→B delta is one split, not significance-tested
  • Attention-MIL varies 0.27–0.60 across runs
  • One dataset, one generator configuration
  • Root-cause map is literature-based, not fab-validated
