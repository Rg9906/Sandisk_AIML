What actually moved the needle

Threshold tuning is the biggest lever, and it is free. Rungs 1 and 2 are the same model at identical AUC-PR. Only the cut point changes, and F1 moves from 0.423 to 0.549. The ranking was never the problem.

Class weighting trades precision for recall without adding information. Per-wafer adaptive weights did not pay off, because the wafer-prior features already hand the model that rate.

SMOTE was run last and hurt, as predicted

Synthetic minority points are interpolated between real failures. With a median Cohen's d of 0.134 those interpolations land squarely inside the pass distribution. Manufacturing more points inside the overlap cannot resolve the overlap.

A3

Multi-resolution feature factory: 2,500 inputs → 88 features

Resolution 1 — die level

500 parametrics → 38 columns

Per-wafer radial and linear gradients regressed out first, then all 500 pooled into one multivariate anomaly score. Individually the median Cohen's d is 0.134; pooled it reaches 3.22. Collapsing to 38 columns also stops the die family winning attribution on column count alone.

Resolution 2 — wafer spatial

Neighbourhood + transductive prior

Multi-scale bad-neighbour ratios at 3×3 through 9×9, directional asymmetry, run lengths, radial distance. Then the two-stage wafer prior: stage one scores the whole wafer, stage two judges each die against its own wafer. Cross-fitted to avoid the stacking leak.

Resolution 3 — sub-die block

2,000 readings → 25 statistics

Mean, spread, percentiles, hot-block count and fraction, longest contiguous hot run, cluster centroid and spread, entropy. Order-aware because the readings are measurably ordered.

A4

Dual-engine benchmark & the honest verdict

Model A — baseline

—

LightGBM over die parametrics, spatial features and the wafer prior. Deterministic, CPU-only, exact SHAP.

Model B — shipped

—

Identical estimator, identical hyper-parameters. The only difference is the appended block columns, so the delta measures the data rather than two modelling choices. That is what deliverable 3 actually asks.

Attention-MIL branch

—

Gated attention over 100 chunks of 20 blocks, late-fused with the tabular branch. Built, measured, and it did not beat statistical pooling. Retained because its attention weights give Model B a block interpretability artifact pooling cannot produce.

Honest engineering verdict. We built it and measured it against plain statistical pooling on identical splits, features and eligible dies. Pooling won on ranking quality, so pooling is what ships. The problem statement asks for improvement or lack thereof, and this is the lack thereof, reported rather than buried.

A5

Resolution-decomposed attribution → cleanroom dispatch

Additive signed tree-SHAP, grouped by resolution

Every column carries a prefix that names its resolution: sp_ spatial, bl_ block, everything else die. SHAP is additive in the logit, so summing signed contributions within each family gives its genuine share. One source of truth, no second bookkeeping system.

Why signed, not absoluteAbsolute sums would hand the die family attribution on column count
Block explanationAttention weights are the pooling operation itself

Crucial engineering discrimination

Edge-Loc versus Scratch. Both render as elongated clusters near the wafer edge. One traces to irregular anneal temperature and load-lock valve impurities; the other to mechanical handling damage. Thermal tuning versus a robot inspection. A system that names the pattern but not the module sends the fab after the wrong tool, and the excursion continues while everyone watches the wrong sensor.
